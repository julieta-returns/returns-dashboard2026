Overview

What this dashboard is

This page reads live data straight from the "CS Dashboard 2026" Google Sheet every time it's opened. Nothing is cached in the page itself, so if the sheet changes, reloading the page shows the new numbers. There are two kinds of sections: "Selected period", which responds to the From/To filter near the top, and "Trends" / the "Products" panel, which always show the full history regardless of that filter.

Filter bar

From / To week filter

Pick a From week and a To week to define the period you want to look at — it can be a single week or a longer stretch. Everything under "Selected period" (the four KPI tiles, "Top return reasons", "Outcome", and the "Return detail" table) recalculates for exactly that range.

Whatever range you pick, the dashboard automatically compares it against the immediately preceding period of the same length. Select 1 week and it compares against the prior week; select 4 weeks and it compares against the 4 weeks before that. The note under the filter bar spells out exactly which weeks are being compared. "Reset" jumps back to just the most recent week.

Selected period

The four KPI tiles

  • Return rate — last matured cohort. The only tile that ignores the From/To filter on purpose. It shows the return rate of the most recent "matured" cohort (a group of orders delivered in the same week, once enough time has passed that we trust the number — see "Return rate by purchase cohort" below). It needs the Shopify enrichment data to populate.
  • Returns. Count of returns submitted in the selected period, with the percent change vs. the prior period of equal length underneath.
  • Return value. Total refund amount for the selected period, same comparison logic.
  • Avg days to return. Average number of days between a customer receiving their order and submitting the return, for the selected period. Needs the Shopify "delivered at" data to calculate, same as the cohort chart.
Selected period

Top return reasons / Outcome

Top return reasons groups every return in the selected period by its parent reason (e.g. "Didn't fit", "Changed my mind", "Defective") and shows the most common ones. Outcome shows what actually happened to those returns — refunded, exchanged, store credit, etc. Both update with the From/To filter.

All-time, not filtered

Products panel

This is the one built for the Product team specifically. On the left is every product (variants like different colors or sizes are merged into one product line — "Ekster Cardholder Pro, Jet Black" and "Ekster Cardholder Pro, Olive" both count under "Ekster Cardholder Pro"), sorted by how many times it's ever been returned. Click a product to see, on the right: its all-time return count, its average days to return, a full breakdown of every return reason it has ever had (not just the top 3), and its customers' actual comments, most recent first.

This panel deliberately ignores the From/To filter above it, because the point is to see a product's real pattern over its whole history, not get thrown off by one unusually bad or good week. If you want a specific week's or month's detail instead, use the "Return detail" table underneath it.

Selected period

Return detail table

One row per returned line item, limited to the From/To period selected above. Use the search box to filter by product, SKU, reason, or comment text. Capped at 500 rows at a time for speed — narrow the period or the search if you need to see more than that.

Trends — always all-time

Return rate by purchase cohort

Not the same thing as "returns processed that week." This groups orders by the week they were delivered, then asks: of everyone who received their order that week, what percent eventually returned it? A cohort stays "Provisional" (shown in gray) until Ekster's full return window (100 days) has passed for every order in it — until then the rate can still go up as more returns come in. Once the window has closed it becomes "Matured" (shown in blue) and the number is final. Needs the Shopify enrichment data to calculate at all.

Trends — always all-time

Returns per week / Return value per week

Simple weekly counts and totals for the last 12 weeks, straight from the "Loop returns (weekly)" tab. These are about when a return was submitted, not when the original order was delivered — that distinction is what separates this from the cohort chart above.

Trends — always all-time

CSAT — return tickets vs. all tickets

Average customer satisfaction survey score by week, comparing tickets that were about a return against the overall average across all support tickets. Useful for spotting whether returns are dragging satisfaction down relative to everything else.

Data

Where the numbers come from

Everything on this page is read directly from four tabs in the "CS Dashboard 2026" sheet: "Loop returns" (one row per returned line item — the rawest data), "Loop returns (weekly)" (that same data pre-aggregated per week), "Return rate (cohort)", and "Return tickets". A weekly Google Apps Script keeps those tabs updated from Gorgias, Loop Returns, and Shopify. If a section looks empty, it almost always means that script hasn't had valid Shopify credentials yet, or hasn't run for that week — not a bug in this page.

Reads the "Loop returns", "Loop returns (weekly)", "Return rate (cohort)" and "Return tickets" tabs directly from the sheet. "Product" groups by the text before " – " in Loop's product title (e.g. "Ekster Cardholder Pro – Jet Black" → "Ekster Cardholder Pro"); a title with no separator shows as-is. The cohort return rate depends on the Shopify enrichment columns — it stays empty until a script run has valid Shopify credentials.
