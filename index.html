▶Overview

What this dashboard is

This page reads live data straight from the "CS Dashboard 2026" and "Returns Dashboard 2026" Google Sheets every time it's opened — nothing is cached, so reloading shows whatever is in the sheets right now. There are two kinds of sections: "Selected period" (the KPI tiles, Outcome, Products panel, Return detail, the two carrier charts and the reserve estimate), which all respond to the From/To filter near the top, and "Trends", which always shows the full history regardless of that filter.

▶Filter bar

From / To week filter

Pick a From week and a To week to define the period you want to look at — a single week or a longer stretch. Everything under "Selected period" (the KPI tiles, "Outcome", the Products panel, the "Return detail" table, both returns-by-carrier charts, and the reserve estimate) recalculates for exactly that range.

Whatever range you pick, it's automatically compared against the immediately preceding period of the same length — 1 week vs. the prior week, 4 weeks vs. the 4 weeks before that. The note under the filter bar spells out exactly which weeks are being compared. "Reset" jumps back to just the most recent week.

It also carries through to the "Trends" charts below (returns/value per week, return rate by cohort): the weeks inside your selected range are shown at full color there, everything else dimmed, so you can see where the period you're looking at sits inside the longer trend.

▶Selected period

The KPI tiles
  • Return rate — last matured cohort. The only tile that ignores the From/To filter on purpose. It's the return rate of the most recent "matured" cohort (see "Return rate by purchase cohort" below). Needs the Shopify enrichment data to populate.
  • Returns. The headline number is orders — one return = one order, even if that order has several products in it, so an order returning 5 products and another returning 2 counts as 2 here, not 7. The percent change vs. the prior period is underneath. The smaller line below that shows the total product-level returns instead (7, in that example) — that's the same count the Outcome chart's slices add up to, since Outcome is tallied per product/line item, not per order. That's the difference if those two numbers ever look like they "don't match": they're answering different questions on purpose.
  • Avg days to return. Average days between delivery and the return being submitted, for the selected period. Needs the Shopify "delivered at" data, same as the cohort chart.
  • CSAT — return tickets. Average satisfaction score for return-related support tickets in the selected period, weighted by how many surveys were actually scored each week (a week with more responses counts for more than a week with one or two).
▶Selected period

Outcome

What actually happened to the returns in the selected period: refunded, exchanged, store credit, etc. Hover a slice to see its return value (total refund $) alongside the count — that's instead of its own KPI tile, to keep it attached to the outcome it belongs to. (A breakdown by return reason lives in the Products panel below instead, where it's more useful grouped by product.)

The line under the chart ("Of $X in returned value...") compares "Total return value" (the value of what was returned, whatever the outcome) against "Total refund amount" (actual cash refunded). The gap between them is what stayed in the business as store credit or an exchange instead of leaving as cash — a finance-relevant number the pie chart alone doesn't show.

▶Selected period

Products panel

Built for the Product team specifically. On the left is every product (variants like different colors or sizes are merged — "Ekster Cardholder Pro, Jet Black" and "..., Olive" both count under "Ekster Cardholder Pro"), sorted by how many times it was returned in the selected period. Click one to see, on the right: its return count and average days to return for that period, a full breakdown of every return reason it had, and its customers' actual comments, most recent first.

Click a bar in the reasons chart to narrow the comments list to just that reason (it turns orange while selected) — click it again, or use "clear filter", to see every comment for the product again.

Below the reasons chart, a small histogram shows how many days after delivery this product's returns actually happened. A cluster in the first few days points more toward a defect, packaging, or sizing problem; returns spread out over weeks look more like ordinary buyer's remorse.

This panel now follows the From/To filter above it, so it always matches what the scorecards and Outcome chart are showing. For the raw row-by-row detail instead, use the "Return detail" table underneath it.

▶Selected period

Return detail table

One row per returned line item, limited to the From/To period selected above. Search filters by product, SKU, reason, or comment text. Capped at 500 rows at a time — narrow the period or the search to see more.

▶Selected period

Returns by carrier

Counts returns by the shipping carrier that delivered the order, pulled from Shopify's own tracking info on the fulfillment. Added 2026-10-05 specifically to give the GOFO carrier investigation hard numbers instead of anecdotes from individual tickets.

This is a COUNT, not a rate — it doesn't yet know how many orders each carrier shipped in total, only how many of its deliveries came back. A carrier that ships more volume will naturally show more returns here even if its return RATE is normal; treat this as a starting point for the conversation, not a finished verdict on any one carrier.

Only populates going forward, or for a week re-synced after 2026-10-05 (running "backfillLoopReturnComments" once re-syncs every historical week and fills this in for all of them).

Added 2026-10: a second chart right below it narrows the same carrier breakdown to only returns whose reason is "Order wasn't delivered on time" — the one reason that's genuinely about the carrier, not the product. It's a small-numbers chart since that reason is rare; an empty result there is normal, not a sign something's broken.

▶Selected period

Return reserve estimate

For the cohort weeks in your selected period that are still "Provisional" (inside Ekster's 100-day return window), this projects how many more returns are likely before that window closes, and what that's likely to cost in refunds. The projection applies the average return rate of the last several already-"Matured" cohorts to the provisional cohort's order count, then subtracts what's already come back — the rest is the projected remainder. The $ estimate multiplies that by the average refund-per-return seen in the selected period.

This is a projection, not a committed number — treat it as finance's starting point for a refund reserve, not a guarantee. If every cohort in the selected period has already matured, there's nothing left to project and the tile says so.

▶Trends — all-time

Return rate by purchase cohort

Not the same as "returns processed that week." This groups orders by the week they were delivered, then asks: of everyone who received their order that week, what percent eventually returned it? A cohort stays "Provisional" (gray) until Ekster's full return window (100 days) has passed for every order in it — the rate can still go up until then. Once the window closes it becomes "Matured" (blue) and the number is final. Needs the Shopify enrichment data to calculate at all.

▶Trends — all-time

Returns / value per week

Simple weekly counts and totals for the last 12 weeks, from "Loop returns (weekly)". These are about when a return was submitted, not when the original order was delivered — that's what separates them from the cohort chart above.

▶Trends — all-time

CSAT — return tickets vs. all tickets

Average satisfaction survey score by week, return-related tickets vs. the overall average across all support tickets. Useful for spotting whether returns are dragging satisfaction down relative to everything else.

▶Trends — all-time

Outcome mix over time

Each week's returns broken down as a % of refund vs. exchange vs. store credit, last 12 weeks. Unlike the Outcome pie chart above (which is for the selected period only), this one always shows the last 12 weeks regardless of the From/To filter, so you can see whether the mix is trending in a direction — a growing refund share means more cash leaving the business instead of staying in as credit or exchange.

▶Data

Where the numbers come from

Five tabs in the "CS Dashboard 2026" sheet: "Loop returns" (one row per returned line item — the rawest data), "Loop returns (weekly)" (the same data pre-aggregated per week), "Return rate (cohort)", "Return tickets", and "Product launch dates". A weekly Google Apps Script keeps those updated from Gorgias, Loop Returns, and Shopify. If a section looks empty, it's almost always that the script hasn't had valid Shopify credentials yet, or hasn't run for that week yet — not a bug in this page.

▶New products

New products, launched in the last N weeks

Products Shopify says were published to the online store in the last 8 weeks (editable in the dashboard's source if that window ever needs to change), with how many returns they've had since THEIR OWN launch date — not since the From/To filter above. A product that's only been live 2 weeks is judged on those 2 weeks, so a bad early signal doesn't have to wait to show up until it's buried in a bigger all-time number.

"Launch date" is Shopify's publishedAt (when it actually went live on the storefront), falling back to createdAt only for the rare product that's never been published. Needs "Product launch dates" populated — run syncProductLaunchDates once in Apps Script for an immediate first fill; it also runs automatically every week after that.

Reads the "Loop returns", "Loop returns (weekly)", "Return rate (cohort)" and "Return tickets" tabs directly from the sheet. "Product" groups by the text before " – " in Loop's product title (e.g. "Ekster Cardholder Pro – Jet Black" → "Ekster Cardholder Pro"); a title with no separator shows as-is. The cohort return rate depends on the Shopify enrichment columns — it stays empty until a script run has valid Shopify credentials.
